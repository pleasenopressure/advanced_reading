先明确一个最重要的关系：

> **SFT 和 LoRA 不是两种并列的训练方法。**

- **SFT（Supervised Fine-Tuning）**回答的是：用什么训练数据、什么目标函数，让模型学习什么行为。
    
- **LoRA（Low-Rank Adaptation）**回答的是：训练时具体更新哪些参数，以及怎样以较低成本更新参数。
    

所以常见的两种方案其实是：

```text
全参数 SFT：使用 SFT 数据，更新模型的大部分或全部参数
LoRA SFT：使用同样的 SFT 数据，但只训练 LoRA 新增的小矩阵
```

文档将预训练知识、SFT 和 LoRA 都归入参数化记忆，因为训练后获得的知识或行为，不再以可读文本存储，而是编码在模型或适配器的数值参数中。

# 一、案例目标：让机器人学会主持讨论

假设我们有一个预训练聊天模型 `BaseModel-7B`。

它已经会说英语、能理解对话，但没有学过你的机器人主持规则。

输入如下：

```json
{
  "topic": "Should students use AI for homework?",
  "participants": [
    {"name": "Jack", "silent_seconds": 20},
    {"name": "Mary", "silent_seconds": 195}
  ],
  "last_speaker": "Jack",
  "recent_dialogue": "Jack argued that AI can save students time."
}
```

未经训练的模型可能回答：

```text
Let's continue the discussion. Does anyone have another opinion?
```

这个回答不算错，但没有做到：

1. 识别 Mary 已经沉默超过 180 秒；
    
2. 主动邀请 Mary；
    
3. 延续当前话题；
    
4. 使用温和、无压迫感的表达。
    

我们希望模型稳定输出：

```text
Mary, we haven't heard from you for a little while.
What's your perspective on Jack's point that AI can save students time?
```

更重要的是，在推理时我们不想每次都添加下面这段规则：

```text
当参与者沉默超过 180 秒时，请温和邀请他发言，
并把问题和当前讨论内容联系起来。
```

而是希望模型经过训练后，**自己形成这种行为倾向**。

这就是我们要产生的“参数化记忆”。

---

# 二、第一步：构造 SFT 数据

## 1. 一个 SFT 样本由什么组成

最简单的 SFT 样本包含：

```text
输入 Prompt + 理想输出 Answer
```

例如：

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You are a discussion-facilitating robot."
    },
    {
      "role": "user",
      "content": "Topic: Should students use AI for homework?\nJack silent: 20 seconds\nMary silent: 195 seconds\nJack said AI can save students time."
    },
    {
      "role": "assistant",
      "content": "Mary, we haven't heard from you for a little while. What's your perspective on Jack's point that AI can save students time?"
    }
  ]
}
```

其中：

- `system + user` 是模型的输入；
    
- `assistant` 是我们希望模型学习的目标输出；
    
- 目标输出通常由人工编写、人工审核，或者先由更强模型生成再人工检查。
    

SFT 的核心思想就是让模型模仿这些高质量示范。InstructGPT 的训练流程中也包含使用人工示范数据进行监督微调的阶段。([arXiv](https://arxiv.org/abs/2203.02155?utm_source=chatgpt.com "Training language models to follow instructions with ..."))

---

## 2. 不能只准备一种样本

假设所有训练样本都是：

```text
Mary 沉默 190 秒 → 邀请 Mary
```

模型可能学到错误的表面规律：

> 只要看见 Mary，就邀请 Mary。

所以必须构造有变化的数据。

### 正触发样本

```json
{
  "silent_seconds": 220,
  "expected_action": "invite_silent_participant"
}
```

目标：

```text
Alex, I'd be interested to hear your view. Do you think AI affects critical thinking?
```

### 不触发样本

```json
{
  "silent_seconds": 45,
  "expected_action": "continue_normally"
}
```

目标：

```text
That's an interesting distinction. Jack, could you explain what kinds of tasks you think AI should handle?
```

### 刚好低于阈值

```json
{
  "silent_seconds": 175,
  "expected_action": "do_not_invite_yet"
}
```

### 刚好高于阈值

```json
{
  "silent_seconds": 185,
  "expected_action": "invite"
}
```

### 多人都沉默

```json
{
  "participants": [
    {"name": "Jack", "silent_seconds": 205},
    {"name": "Mary", "silent_seconds": 240}
  ]
}
```

目标可以优先邀请沉默更久的人。

### 主导者存在，但沉默阈值未触发

```json
{
  "Jack_talk_ratio": 0.82,
  "Mary_silent_seconds": 120
}
```

目标应该处理“发言失衡”，而不是错误地套用“三分钟沉默”规则。

---

## 3. 一个更合理的训练集

假设我们准备 20,000 条样本：

```text
8,000 条：参与者沉默超过阈值
5,000 条：没有人超过阈值
3,000 条：发言比例严重失衡
2,000 条：发生长时间全场静默
2,000 条：出现不礼貌或冲突表达
```

每种情况还要变化：

- 参与者姓名；
    
- 讨论主题；
    
- 沉默时间；
    
- 对话长度；
    
- 最近发言内容；
    
- 目标回答措辞；
    
- 是否真的应该介入。
    

否则模型可能只记住模板，而没有学会规则。

---

# 三、第二步：文本如何变成训练数据

## 1. Chat Template 序列化

原始消息通常会被拼成一个序列：

```text
<|system|>
You are a discussion-facilitating robot.
<|user|>
Topic: Should students use AI for homework?
Jack silent: 20 seconds
Mary silent: 195 seconds
Jack said AI can save students time.
<|assistant|>
Mary, we haven't heard from you for a little while...
<|end|>
```

Tokenizer 再把文本转换为 Token ID：

```text
[1, 832, 374, 264, 10422, ..., 19834, 11, 584, 3412, ...]
```

这些整数就是模型真正接收的输入。

假设整个序列有 $T$ 个 Token：

$$  
x_1,x_2,\ldots,x_T  
$$

模型的任务是根据前面的 Token，预测下一个 Token。

---

## 2. 为什么要做 Label Masking

我们通常只希望模型学习 `assistant` 的答案，而不是要求它预测用户输入。

因此标签可能是：

```text
Token                         Label
<|system|>                    -100
You                           -100
are                           -100
...
<|user|>                      -100
Mary                          -100
silent                        -100
195                           -100
...
<|assistant|>                 -100 或目标开始
Mary                          Mary 的 token ID
,                             , 的 token ID
we                            we 的 token ID
haven't                       haven't 的 token ID
...
```

在 PyTorch 和 Transformers 的常见实现中，标签值 `-100` 表示：

> 这个位置不参与交叉熵损失计算。

所以模型虽然读取 System 和 User Token，但主要通过 Assistant Token 的预测错误接受训练。

可以形式化为：

$$  
m_t =  
\begin{cases}  
0,& \text{输入部分}\  
1,& \text{Assistant 输出部分}  
\end{cases}  
$$

训练损失为：

$$  
\mathcal{L}(\theta)

-\frac{1}{\sum_t m_t}  
\sum_{t=1}^{T}  
m_t  
\log p_\theta(x_t\mid x_{<t})  
$$

其中：

- $\theta$：模型参数；
    
- $x_{<t}$：第 $t$ 个 Token 前面的所有 Token；
    
- $p_\theta(x_t\mid x_{<t})$：模型为正确 Token 分配的概率。
    

---

# 四、第三步：模型如何产生预测

以输出的第一个单词 `Mary` 为例。

模型读取：

```text
Topic: ...
Jack silent: 20 seconds
Mary silent: 195 seconds
Jack said ...
<|assistant|>
```

经过 Embedding 和多层 Transformer 后，得到最后一个位置的隐藏状态：

$$  
h_t\in\mathbb{R}^{d}  
$$

假设模型隐藏维度：

$$  
d=4096  
$$

于是：

$$  
h_t\in\mathbb{R}^{4096}  
$$

输出层将隐藏状态映射到整个词表：

$$  
z_t=W_{\text{vocab}}h_t+b  
$$

如果词表有 50,000 个 Token：

$$  
z_t\in\mathbb{R}^{50000}  
$$

这里的每个数叫 Logit。

经过 Softmax：

$$  
p_i=\frac{e^{z_i}}{\sum_j e^{z_j}}  
$$

得到各个 Token 的概率。

训练前，模型可能输出：

```text
Token       概率
Let's       0.31
Could       0.15
Mary        0.08
Jack        0.06
What        0.05
其他         0.35
```

正确答案是 `Mary`，所以这个位置的损失是：

$$  
-\log 0.08\approx2.526  
$$

模型为正确答案分配的概率越低，损失越大。

经过训练以后，概率可能变为：

```text
Token       概率
Mary        0.61
Let's       0.07
Could       0.06
Jack        0.02
其他         0.24
```

此时损失为：

$$  
-\log 0.61\approx0.494  
$$

这些概率只是用于说明的假设数字，但它展示了训练目标：

> 不断提高正确目标 Token 的条件概率。

---

# 五、全参数 SFT 是如何实现的

## 1. 什么叫“全参数”

一个 Transformer 模型中通常包含很多参数矩阵，例如：

```text
Token Embedding
Attention:
    Wq
    Wk
    Wv
    Wo

MLP:
    W_gate
    W_up
    W_down

LayerNorm
Output Head
```

以 Attention 为例：

$$  
Q=XW_Q  
$$

$$  
K=XW_K  
$$

$$  
V=XW_V  
$$

$$  
\operatorname{Attention}(Q,K,V)

\operatorname{softmax}  
\left(  
\frac{QK^\top}{\sqrt{d_k}}  
\right)V  
$$

全参数 SFT 中，这些矩阵通常都可以接收梯度并被更新：

```python
for parameter in model.parameters():
    parameter.requires_grad = True
```

---

## 2. 前向传播

模型接收一个 Batch：

```python
outputs = model(
    input_ids=input_ids,
    attention_mask=attention_mask,
    labels=labels,
)

loss = outputs.loss
```

模型依次完成：

```text
Token ID
   ↓
Embedding
   ↓
Transformer 第 1 层
   ↓
Transformer 第 2 层
   ↓
...
   ↓
Transformer 第 N 层
   ↓
Vocabulary logits
   ↓
Cross-entropy loss
```

---

## 3. 反向传播

调用：

```python
loss.backward()
```

PyTorch 的 Autograd 会沿计算图反向计算：

$$  
\frac{\partial\mathcal{L}}{\partial\theta}  
$$

也就是：

> 每个可训练参数发生一个微小变化，会让 Loss 增加还是减少，以及变化幅度有多大。

PyTorch 的自动微分系统负责追踪前向传播中的张量运算，并从标量损失反向计算参数梯度。([PyTorch Documentation](https://docs.pytorch.org/docs/stable/autograd.html?utm_source=chatgpt.com "Automatic differentiation package - torch.autograd"))

---

## 4. 参数更新

以最简单的 SGD 为例：

$$  
\theta_{t+1}

\theta_t-\eta  
\frac{\partial\mathcal{L}}{\partial\theta_t}  
$$

其中：

- $\eta$ 是学习率；
    
- 梯度为正，参数向负方向移动；
    
- 梯度为负，参数向正方向移动。
    

假设一个参数当前是：

$$  
w=0.12000000  
$$

梯度是：

$$  
\frac{\partial\mathcal L}{\partial w}=-0.003  
$$

学习率：

$$  
\eta=2\times10^{-5}  
$$

那么一次 SGD 更新后：

$$  
w'

0.12-(2\times10^{-5})(-0.003)  
$$

$$  
w'=0.12000006  
$$

单个参数只改变了一点点。

但是模型有数十亿个参数，每个训练 Batch 都会产生大量这样的微小变化。经过数千个更新步骤，它们共同形成新的行为模式。

实际训练更常使用 AdamW，而不是最简单的 SGD。AdamW 会为每个参数维护梯度的一阶和二阶统计量，再调整实际更新幅度。

---

## 5. 一个简化的全参数 SFT 训练循环

```python
import torch
from torch.optim import AdamW

model.train()

# 全部参数参与训练
for parameter in model.parameters():
    parameter.requires_grad = True

optimizer = AdamW(
    model.parameters(),
    lr=2e-5,
    weight_decay=0.01,
)

for batch in train_loader:
    optimizer.zero_grad(set_to_none=True)

    input_ids = batch["input_ids"].to(model.device)
    attention_mask = batch["attention_mask"].to(model.device)
    labels = batch["labels"].to(model.device)

    # 1. 前向传播
    outputs = model(
        input_ids=input_ids,
        attention_mask=attention_mask,
        labels=labels,
    )
    loss = outputs.loss

    # 2. 反向传播
    loss.backward()

    # 3. 梯度裁剪，避免梯度过大
    torch.nn.utils.clip_grad_norm_(
        model.parameters(),
        max_norm=1.0,
    )

    # 4. 更新模型参数
    optimizer.step()
```

训练完成后：

```text
原始参数：θ₀
训练变化：Δθ
新参数：  θ* = θ₀ + Δθ
```

这里的 $\Delta\theta$ 就承载了新学到的行为。

# 六、为什么这叫“参数化记忆”

训练前，模型必须看到明确指令：

```text
当参与者沉默超过三分钟时，温和地邀请他发言。
```

否则它不一定会执行。

经过大量 SFT 样本后，即使推理 Prompt 只包含：

```text
Mary silent: 195 seconds
Jack said that AI saves students time.
```

模型也更可能输出：

```text
Mary, what's your perspective on Jack's point?
```

说明训练信息已经不需要以完整文本形式放进 Prompt，而是通过参数变化影响了模型的条件概率分布：

$$  
p_{\theta^*}(y\mid x)  
\neq  
p_{\theta_0}(y\mid x)  
$$

例如：

```text
训练前：
P(温和邀请 Mary | Mary 沉默 195 秒) = 0.12

训练后：
P(温和邀请 Mary | Mary 沉默 195 秒) = 0.79
```

这不是说模型里存在一个明确字段：

```json
{
  "silent_threshold": 180
}
```

而是大量参数共同发生变化，使模型更容易：

- 注意到 `Mary`；
    
- 注意到 `195 seconds`；
    
- 将 195 秒与“沉默过久”关联；
    
- 联系 Jack 的上一句话；
    
- 生成邀请式表达；
    
- 避免批评 Mary。
    

因此，参数化记忆通常是一种**分布式记忆**：

> 一条规则可能分散编码在许多层、许多注意力头和许多参数中。

我们通常无法指出：

```text
第 372 层的第 921 个参数，
专门保存了“三分钟沉默规则”。
```

---

# 七、全参数 SFT 的成本为什么高

假设模型有 70 亿参数。

仅以 BF16 保存权重：

$$  
7\times10^9\times2\text{ bytes}  
\approx14\text{ GB}  
$$

训练时还可能需要保存：

- 模型权重；
    
- 梯度；
    
- Adam 一阶动量；
    
- Adam 二阶动量；
    
- 某些配置下的 FP32 主权重；
    
- 前向传播激活值；
    
- Attention 中间结果。
    

仅两个 FP32 Adam 状态大约就是：

$$  
7\times10^9\times4\times2  
\approx56\text{ GB}  
$$

因此全参数 SFT 的显存需求远高于单纯推理。

这也是为什么需要 LoRA。

---

# 八、LoRA 如何实现同一个 SFT

LoRA 的核心做法是：

> 冻结原模型权重，不直接更新大矩阵，而是在大矩阵旁边添加两个很小的低秩矩阵。

LoRA 原始论文将预训练权重冻结，并在 Transformer 层中注入可训练的低秩分解矩阵，从而显著减少需要训练的参数。([arXiv](https://arxiv.org/abs/2106.09685?utm_source=chatgpt.com "LoRA: Low-Rank Adaptation of Large Language Models"))

---

# 九、从普通线性层开始理解 LoRA

原始线性层：

$$  
y=W_0x  
$$

假设：

$$  
W_0\in\mathbb{R}^{4096\times4096}  
$$

这个矩阵有：

$$  
4096\times4096=16,777,216  
$$

大约 1678 万个参数。

全参数 SFT 会直接更新：

$$  
W_0  
$$

得到：

$$  
W'=W_0+\Delta W  
$$

LoRA 不直接训练完整的 $\Delta W$，而是假设它可以近似为两个低秩矩阵的乘积：

$$  
\Delta W=BA  
$$

其中：

$$  
A\in\mathbb{R}^{r\times4096}  
$$

$$  
B\in\mathbb{R}^{4096\times r}  
$$

如果设置：

$$  
r=8  
$$

那么：

$$  
A\in\mathbb{R}^{8\times4096}  
$$

$$  
B\in\mathbb{R}^{4096\times8}  
$$

参数总数：

$$  
8\times4096+4096\times8

65,536  
$$

相对于原矩阵：

$$  
\frac{65,536}{16,777,216}  
\approx0.39%  
$$

也就是说，这个线性层只需要训练原参数量的约 0.39%。

---

# 十、LoRA 的完整前向计算

加入缩放后，LoRA 线性层一般写作：

$$  
y

W_0x+  
\frac{\alpha}{r}BAx  
$$

其中：

- $W_0$：冻结的原始权重；
    
- $A$：降维矩阵；
    
- $B$：升维矩阵；
    
- $r$：LoRA Rank；
    
- $\alpha$：缩放系数；
    
- $\alpha/r$：LoRA 分支的缩放。
    

例如：

```text
输入 x：4096 维
    ↓ A
压缩成：8 维
    ↓ B
恢复成：4096 维
```

也就是：

$$  
x\in\mathbb{R}^{4096}  
$$

$$  
Ax\in\mathbb{R}^{8}  
$$

$$  
B(Ax)\in\mathbb{R}^{4096}  
$$

可以把它理解成：

> LoRA 只允许模型在一个较小的低维子空间里学习参数变化。

---

# 十一、为什么低秩可能有效

完整的参数变化：

$$  
\Delta W\in\mathbb{R}^{4096\times4096}  
$$

理论上可以拥有 1600 多万个独立自由度。

但是让模型学习“温和邀请沉默者”通常不需要完全重写整层能力。

基础模型已经知道：

- 什么是沉默；
    
- 如何提出问题；
    
- 如何使用礼貌英语；
    
- 怎样总结前文；
    
- 人名如何在句子中使用。
    

新任务主要是重新组合这些已有能力：

```text
识别沉默状态
+
选择沉默参与者
+
联系当前话题
+
调用礼貌提问模式
```

因此所需的参数变化可能集中在一个较低维度的方向上。LoRA 正是利用“适配所需的权重更新可能具有较低内在秩”这一假设。([arXiv](https://arxiv.org/abs/2106.09685?utm_source=chatgpt.com "LoRA: Low-Rank Adaptation of Large Language Models"))

---

# 十二、LoRA 具体加在哪些位置

Transformer 的 Attention 中包含：

$$  
W_Q,W_K,W_V,W_O  
$$

常见 LoRA 配置可能只加在：

```text
q_proj
v_proj
```

也可能加在：

```text
q_proj
k_proj
v_proj
o_proj
```

还可以进一步加到 MLP：

```text
gate_proj
up_proj
down_proj
```

例如只对 32 层模型的 `q_proj` 和 `v_proj` 使用 Rank 8 LoRA。

每个投影矩阵增加：

$$  
65,536  
$$

个参数。

32 层、每层两个矩阵：

$$  
65,536\times2\times32

4,194,304  
$$

约 419 万个参数。

相对于 70 亿模型：

$$  
\frac{4.19\text{M}}{7\text{B}}  
\approx0.06%  
$$

这只是一个基于假设结构的计算示例，实际数量取决于模型维度、层数和目标模块。

# 十三、LoRA 参数如何初始化

常见初始化方式是：

- $A$ 使用随机值；
    
- $B$ 初始化为 0。
    

所以训练刚开始时：

$$  
BA=0  
$$

因此：

$$  
y=W_0x  
$$

也就是说，刚加入 LoRA 时，模型输出和原始模型相同，不会因为随机 Adapter 立即破坏模型行为。

---

## 一个有意思的梯度细节

LoRA 输出为：

$$  
y=W_0x+sBAx  
$$

其中：

$$  
s=\frac{\alpha}{r}  
$$

对于 $B$ 的梯度：

$$  
\frac{\partial\mathcal L}{\partial B}=

s  
\frac{\partial\mathcal L}{\partial y}  
(Ax)^\top  
$$

因为 $A$ 是随机非零的，所以训练第一步时，$B$ 通常可以获得非零梯度。

对于 $A$：

$$  
\frac{\partial\mathcal L}{\partial A}

sB^\top  
\frac{\partial\mathcal L}{\partial y}  
x^\top  
$$

因为初始：

$$  
B=0  
$$

所以第一步时，$A$ 的梯度通常也是 0。

第一步主要先更新 $B$；当 $B$ 不再为零后，后续步骤中 $A$ 也开始获得梯度。

# 十四、LoRA SFT 的反向传播发生在哪里

全参数 SFT：

```text
Loss
 ↓
输出层
 ↓
Transformer 所有层
 ↓
Wq、Wk、Wv、Wo、MLP 等原始参数全部更新
```

LoRA SFT：

```text
Loss
 ↓
输出层和 Transformer 反向传播
 ↓
计算到 LoRA 分支
 ↓
只保存并应用 A、B 的梯度
 ↓
原始 W₀ 保持不变
```

虽然梯度信号仍然需要穿过整个网络，原始参数却设置为：

```python
parameter.requires_grad = False
```

因此不会为它们保存和应用参数梯度。

训练后：

```text
基础模型：完全不变
LoRA Adapter：保存新学到的行为
```

这使一个基础模型可以配多个适配器：

```text
Base Model
├─ discussion-mediator-lora
├─ code-review-lora
├─ medical-writing-lora
└─ customer-service-lora
```

PEFT 的目标正是只训练少量附加参数，从而降低适配模型的训练和存储成本。([Hugging Face](https://huggingface.co/docs/peft/en/index?utm_source=chatgpt.com "PEFT"))

# 十五、LoRA SFT 的代码结构

下面是一个典型的 Hugging Face PEFT 配置示意：

```python
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

base_model = AutoModelForCausalLM.from_pretrained(
    "your-base-model",
    torch_dtype="bfloat16",
    device_map="auto",
)

lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,

    # 不同模型的模块名称可能不同
    target_modules=[
        "q_proj",
        "v_proj",
    ],

    bias="none",
    task_type="CAUSAL_LM",
)

model = get_peft_model(
    base_model,
    lora_config,
)

model.print_trainable_parameters()
```

内部效果可以近似理解为：

```python
# 原模型参数冻结
for parameter in base_model.parameters():
    parameter.requires_grad = False

# 新增的 LoRA A、B 参数可训练
for parameter in lora_parameters:
    parameter.requires_grad = True
```

训练循环与 SFT 基本一样：

```python
optimizer = AdamW(
    (p for p in model.parameters() if p.requires_grad),
    lr=2e-4,
)

for batch in train_loader:
    optimizer.zero_grad(set_to_none=True)

    outputs = model(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        labels=batch["labels"],
    )

    loss = outputs.loss
    loss.backward()

    torch.nn.utils.clip_grad_norm_(
        model.parameters(),
        max_norm=1.0,
    )

    optimizer.step()
```

注意这里的 LoRA 学习率经常可以比全参数微调更高，但具体值必须通过验证集确定，不能机械地照搬。

# 十六、LoRA 中 Rank、Alpha 和 Dropout 分别是什么

## Rank：`r`

```python
r=8
```

它决定中间低维空间的大小：

```text
4096 → 8 → 4096
```

Rank 越大：

- 可训练参数越多；
    
- 表达能力越强；
    
- 显存和存储成本越高；
    
- 更可能拟合复杂变化。
    

例如：

```text
r = 4：容量较小
r = 8：常见起点
r = 16：更大容量
r = 64：接近更重的适配
```

没有“永远最好”的 Rank，需要通过任务验证。

---

## Alpha：`lora_alpha`

LoRA 分支一般乘：

$$  
\frac{\alpha}{r}  
$$

如果：

```text
r = 8
alpha = 16
```

缩放系数为：

$$  
\frac{16}{8}=2  
$$

于是：

$$  
y=W_0x+2BAx  
$$

Alpha 控制 LoRA 更新对最终输出的相对影响。

---

## LoRA Dropout

```python
lora_dropout=0.05
```

训练时随机丢弃 LoRA 分支中的一部分输入，有助于减少小数据集上的过拟合。

推理时 Dropout 会关闭。

# 十七、训练结束后保存了什么

## 全参数 SFT

保存的是一套新的完整模型：

```text
base-model/
    原始模型：约 14 GB

full-sft-model/
    新模型：约 14 GB
```

新模型的所有权重都可能与原模型不同。

---

## LoRA SFT

只需要保存 Adapter：

```text
base-model/
    原始模型：约 14 GB

discussion-lora/
    adapter_model.safetensors
    adapter_config.json
```

Adapter 可能只有几十 MB 或几百 MB，取决于 Rank、目标模块和模型规模。

推理时有两种方式。

### 动态加载

$$  
y=W_0x+\frac{\alpha}{r}BAx  
$$

基础模型和 Adapter 分开保存。

### 合并权重

先计算：

$$  
W_{\text{merged}}

W_0+\frac{\alpha}{r}BA  
$$

然后正常推理：

$$  
y=W_{\text{merged}}x  
$$

这样推理时不再需要额外计算 LoRA 分支，但合并后要管理新的完整权重副本。

# 十八、参数化记忆究竟在哪里

经过 LoRA SFT 后，“邀请沉默者”的行为主要存储在：

```text
A 矩阵
B 矩阵
```

例如：

```text
layer_0.self_attn.q_proj.lora_A
layer_0.self_attn.q_proj.lora_B
layer_0.self_attn.v_proj.lora_A
layer_0.self_attn.v_proj.lora_B
...
layer_31.self_attn.v_proj.lora_B
```

但是不能直接打开这些矩阵，然后看到：

```text
如果 silence_seconds > 180：
    invite participant
```

你看到的是浮点数：

```text
[
  [ 0.0017, -0.0042,  0.0081, ...],
  [-0.0031,  0.0009, -0.0065, ...],
  ...
]
```

这些浮点数共同改变模型的内部表示和输出概率。

因此，这种记忆具有三个特点：

1. **不可直接阅读**；
    
2. **分布式存储**；
    
3. **通过行为表现出来，而不是通过查询一条记录表现出来**。

# 十九、模型真正“记住”的不是一句话，而是条件映射

我们希望模型学习的是：

$$  
f_\theta(\text{conversation state})  
\rightarrow  
\text{facilitation response}  
$$

更具体地说：

```text
输入特征：
参与者身份
沉默时间
当前话题
上一位发言者
最近发言内容
语气要求

输出行为：
是否介入
邀请谁
怎样承接话题
使用什么语气
```

训练数据不断告诉模型：

```text
这种输入 → 这种输出
```

梯度下降不断修改参数，让目标映射的概率提高。

所以参数化记忆更像：

> 模型学会了一种从输入状态到输出行为的函数。

而不是简单记住一条数据库记录。

# 二十、它可能学错什么

## 1. 学到人名，而不是沉默规则

训练数据里总是 Mary 沉默，模型可能学成：

```text
看到 Mary → 邀请发言
```

解决办法：增加姓名和场景多样性。

---

## 2. 学到具体数字，而不是边界概念

训练数据只有：

```text
195 秒 → 邀请
```

模型可能不能稳定处理：

```text
181 秒
240 秒
3 minutes 20 seconds
```

解决办法：

- 使用多个数值；
    
- 使用不同单位；
    
- 加入阈值两侧样本；
    
- 进行边界测试。
    

---

## 3. 任何沉默都邀请

如果缺少负样本，模型可能在 30 秒时也介入。

因此必须包含：

```text
30 秒 → 不介入
90 秒 → 不介入
175 秒 → 不介入
185 秒 → 介入
240 秒 → 介入
```

---

## 4. 记住语言模板

如果目标回答永远是：

```text
We haven't heard from you for a while...
```

模型可能只会机械复述。

应该提供多种合格表达：

```text
I'd be interested to hear your view.
What do you make of Jack's point?
Mary, how does this compare with your experience?
Would you like to add another perspective?
```

# 二十一、为什么不应该把所有用户记忆都做成 LoRA

假设用户说：

```text
我的项目截止日期是 2026 年 9 月 30 日。
```

理论上可以制作训练样本，让 LoRA 记住它。

但这通常是错误设计，因为：

1. 日期可能改变；
    
2. 精确事实可能被模糊记忆；
    
3. 很难单独删除；
    
4. 每次更新都需要重新训练；
    
5. 训练样本中可能发生记忆污染；
    
6. 用户可能要求“忘记这件事”。
    

这种内容更适合外部记忆：

```json
{
  "fact": "project_deadline",
  "value": "2026-09-30",
  "source": "user_message_id",
  "valid_from": "2026-07-01",
  "status": "active"
}
```

而下面这种稳定能力更适合 SFT/LoRA：

```text
看到项目截止日期时：
分析剩余时间，拆分里程碑，并提示风险缓冲。
```

也就是：

```text
具体事实 → Token 级外部记忆
稳定技能 → 参数化记忆
```

# 二十二、完整流程总结

## 全参数 SFT

```text
1. 收集高质量输入—输出示范
2. 使用 Chat Template 序列化
3. Tokenizer 转换为 input_ids
4. Mask 掉不需要监督的输入 Token
5. 模型前向传播得到 logits
6. 计算目标 Token 的交叉熵损失
7. 反向传播计算所有模型参数梯度
8. AdamW 更新原模型参数
9. 多轮训练后得到 θ* = θ₀ + Δθ
10. 新行为分布式编码在完整模型参数中
```

## LoRA SFT

```text
1. 使用相同的 SFT 数据和交叉熵目标
2. 冻结基础模型 W₀
3. 为目标线性层增加 A、B 矩阵
4. 前向计算 W₀x + (α/r)BAx
5. 反向传播时只更新 A、B
6. 保存小型 Adapter
7. 推理时加载或合并 Adapter
8. 新行为编码在 LoRA 参数 A、B 中
```

最重要的一句话是：

> **SFT 通过示范数据定义模型应该学会什么；LoRA 通过低秩参数更新决定模型以什么方式把这种能力写入参数。**
