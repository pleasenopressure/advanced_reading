> “余弦相似度对长度不敏感”中的“长度”，指的是**向量的模（norm）或绝对大小**，而不是 Query 的文本长度，也不是向量的维度数量。

而且它不仅对 Query 向量的长度不敏感，也对文档向量的长度不敏感。文档中说余弦相似度主要看两个向量方向是否一致，也是这个意思。
假设 Query 的 Embedding 是：$$\mathbf q=[1,1]$$它的向量长度是：$$\|\mathbf q\|=\sqrt{1^2+1^2}=\sqrt{2}$$另一个向量：$$\mathbf d=[10,10]$$虽然 $\mathbf d$比$\mathbf q$长了 10 倍，但它们的方向完全一样
余弦相似度为：
$$\cos(\mathbf q,\mathbf d)
=
\frac{\mathbf q\cdot\mathbf d}
{\|\mathbf q\|\|\mathbf d\|}
=1$$# 6. 为什么向量绝对长度可能是“干扰因素”？

在一些 Embedding 模型中，向量模可能受到很多因素影响，例如：

- 文本表达强度；
- Token 数量；
- 高频特征；
- 模型内部激活幅度；
- 文本是否属于模型熟悉的分布；
- 模型训练方式。

这些因素不一定等价于“语义更相似”。

假设两个句子：

```
Query：如何申请退款？

文档 A：退款怎么申请？
文档 B：退款退款退款退款退款退款退款。
```

文档 B 某些“退款”相关特征的数值可能非常大，但它不一定比文档 A 提供了更匹配、更完整的语义。

余弦相似度会更关注：

> 各个语义特征之间的相对组合是否一致。

而不是只关注数值总体有多大。
# 但不能绝对说“余弦一定最好”

“余弦适合文本检索”成立的前提是：

> 该 Embedding 模型主要把语义编码在向量方向中，或者模型本身就是按照余弦相似度目标训练的。

有些 Embedding 模型可能使用内积训练，并且向量模本身包含有用信息。此时强行归一化或改用余弦，可能损失效果。

因此真实项目中的正确做法不是无脑选择余弦，而是：

1. 查看 Embedding 模型官方推荐的度量；
2. 确认模型输出是否已经归一化；
3. 向量数据库索引度量保持一致；
4. 使用自己的业务检索数据评测。
