因为**递归字符切分**和 **Token 重叠**解决的是两个不同层面的问题：

- 递归字符切分：尽量找到更自然的切分位置；
- Token 重叠：降低切分边界附近的信息丢失。

递归切分只能让边界“更合理”，不能保证相邻代码块完全独立。文档中确实同时提出了约 100 Token 的块和约 15 Token 的重叠。

## 1. 递归切分仍然可能切断上下文

递归切分通常按照类似顺序寻找边界：

```
[
    "\n\n",  # 空行
    "\n",    # 换行
    " ",     # 空格
    ""       # 字符
]
```

它的意思不是：

> 一定按照完整函数或完整类切分。

而是：

> 在不超过目标大小的前提下，尽量选择较自然的字符边界。

假设目标大小只有 100 Token，而一个 Python 函数有 180 Token：

```
def process_document(document):
    cleaned = clean_document(document)
    chunks = split_document(cleaned)

    metadata = build_metadata(document)

    for chunk in chunks:
        chunk.metadata.update(metadata)
        chunk.embedding = embed(chunk.text)

    return chunks
```

即使使用递归切分，这个函数仍然必须被分成两个 Chunk，因为整个函数超过了 100 Token。

可能变成：

```
# Chunk 1
def process_document(document):
    cleaned = clean_document(document)
    chunks = split_document(cleaned)

    metadata = build_metadata(document)
```

```
# Chunk 2
for chunk in chunks:
    chunk.metadata.update(metadata)
    chunk.embedding = embed(chunk.text)

return chunks
```

第二个 Chunk 单独看时存在问题：

- 不知道 `chunks` 从哪里来；
- 不知道 `metadata` 是什么；
- 看不到函数名称；
- 不知道循环属于哪个函数；
- `return chunks` 的作用域不清楚。

递归切分虽然选择了换行位置，但**语义和作用域仍然被切断了**。

## 2. 重叠会把部分边界上下文复制过来

如果设置：

```
chunk_size = 100
chunk_overlap = 15
```

第二个 Chunk 可能会额外包含前一个 Chunk 末尾约 15 Token：

```
# Chunk 2，包含部分重叠内容
metadata = build_metadata(document)

for chunk in chunks:
    chunk.metadata.update(metadata)
    chunk.embedding = embed(chunk.text)

return chunks
```

这样，第二个 Chunk 至少知道：

- `metadata` 是在哪里产生的；
- 后面的 `chunk.metadata.update(metadata)` 与前文有什么关系。

因此，Overlap 相当于给每个边界加一个小的“缓冲区”。

```
原始代码：

AAAAAAA BBBBBBB CCCCCCC DDDDDDD
             ↑ 切分边界

无重叠：

Chunk 1: AAAAAAA BBBBBBB
Chunk 2: CCCCCCC DDDDDDD

有重叠：

Chunk 1: AAAAAAA BBBBBBB
Chunk 2:   BBBBB CCCCCCC DDDDDDD
           └重叠┘
```
