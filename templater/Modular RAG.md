# Modular RAG 中的术语

文档给出的描述是：

```
检索器、重排器、压缩器、路由器、生成器等模块
可以插拔组合
```

## 1. 检索器：Retriever

检索器负责从知识源中找出候选资料。

输入：

```
用户 Query
```

输出：

```
一组可能相关的文档或 Chunk
```

检索器不一定是向量数据库，也可以是：

- BM25 搜索；
- 向量检索；
- SQL 数据库查询；
- 图数据库查询；
- 网络搜索；
- 代码搜索；
- API 查询；
- 企业内部搜索系统。

例如：

```
员工制度问题 → HR 文档检索器
订单状态问题 → SQL 查询器
技术报错问题 → 日志检索器
```

---

## 2. 重排器：Reranker

重排器接收检索器找到的候选结果，然后重新评估其相关性。

输入：

```
Query + 20 个候选 Chunk
```

输出：

```
按照相关性重新排列的 Chunk
```

检索器负责“找得广”，重排器负责“排得准”。

---

## 3. 压缩器：Compressor

压缩器负责缩减检索内容。

它可能执行：

- 提取相关句子；
- 删除重复内容；
- 合并相似 Chunk；
- 对文档进行针对性摘要；
- 删除与 Query 无关的段落；
- 控制上下文 Token 数量。

例如：

```
5 个 Chunk，共 8000 Token
          ↓
压缩器
          ↓
保留 2000 Token 的核心证据
```

---

## 4. 路由器：Router

路由器负责判断：

> 当前问题应该走哪条处理链路、查询哪个数据源、使用哪些模块。

例如用户提出三个问题：

```
1. 公司的年假政策是什么？
2. 我的订单现在在哪里？
3. 帮我总结这份 PDF。
```

路由器可能分别选择：

```
问题 1
→ HR 知识库 RAG

问题 2
→ 订单数据库 API

问题 3
→ 长上下文文档分析
```

更复杂的路由器还可以决定：

- 是否需要 Query Rewrite；
- 是否使用 HyDE；
- 使用关键词检索还是向量检索；
- 查询哪个知识库；
- 是否需要 Rerank；
- 是否调用外部工具；
- 使用哪个 LLM；
- 是否应该拒答。

路由器可以由规则实现：

```
if query_contains_order_id:
    use_order_database()
```

也可以由 LLM 判断：

```
请判断这个问题属于 HR、财务、技术支持还是订单查询。
```

---

## 5. 生成器：Generator

生成器是最终根据证据生成答案的模型或组件。

它通常是 LLM，但不同任务可以使用不同生成器：

```
普通问答 → 快速、便宜的模型
复杂跨文档分析 → 推理能力更强的模型
代码问题 → 代码模型
结构化抽取 → 支持严格 JSON 的模型
```

生成器不仅负责输出文字，还可能负责：

- 输出 JSON；
- 生成引用；
- 生成表格；
- 判断资料是否足够；
- 发现文档冲突；
- 请求进一步检索。

---

## 6. 可插拔组合：Pluggable Components

“可插拔”表示每个模块都相对独立，可以替换，而不需要推翻整个系统。

例如原来使用：

```
OpenAI Embedding
→ pgvector
→ 某个 Reranker
→ GPT 生成
```

后面可以替换成：

```
开源 BGE Embedding
→ Elasticsearch
→ 新的 Cross-Encoder
→ 本地 LLM
```

只要模块之间的输入输出接口保持一致，其他部分不需要大幅修改。

它类似于搭积木：

```
Query Processor
      ↓
Retriever
      ↓
Reranker
      ↓
Compressor
      ↓
Generator
```

每块积木都可以单独更换。

---

## 7. 动态路由：Dynamic Routing

动态路由表示系统不会让所有问题都走同一条固定链路，而是根据问题实时决定。

例如简单问题：

```
“员工手册的文件在哪里？”

→ 传统关键词搜索
→ 返回文件链接
```

复杂问题：

```
“比较旧版和新版员工手册的休假政策变化。”

→ 查询改写
→ 检索两个版本
→ 重排
→ 上下文压缩
→ LLM 跨文档比较
```

数据库问题：

```
“我还有多少天年假？”

→ 调用员工系统 API
→ 不走文档向量检索
```

因此，Modular RAG 的核心不是“模块越多越好”，而是：

> 根据问题选择正确的数据源和最合适的处理流程。
