文档里把 **KD-Tree、VP-Tree** 归为精确最近邻（ENN）方向，并指出：它们在低维空间效果较好，但面对几百、上千维的 Embedding 时，容易因“维度灾难”退化到接近暴力搜索。

下面展开它们具体是怎样建索引、怎样查询和怎样剪枝的。

# 一、先理解它们共同要解决的问题

数据库中有很多向量：
$$x_1,x_2,\ldots,x_n$$

查询向量为 (q)，目标是找到距离最小的向量：
$$x^*=\arg\min_{x_i}d(q,x_i)$$

暴力搜索需要计算：

```text
d(q, x₁)
d(q, x₂)
...
d(q, xₙ)
```

KD-Tree 和 VP-Tree 都试图把向量组织成树，使查询时可以排除一整片“不可能更近”的数据。

它们的共同逻辑是：

```text
把数据递归分区
        ↓
查询时先进入最可能包含答案的分区
        ↓
根据当前最近距离判断其他分区是否还有必要访问
        ↓
能证明不可能更近，就剪枝
```

但它们的**分区方式不同**：

- KD-Tree：根据坐标轴切分空间；
    
- VP-Tree：根据到某个中心点的距离切分空间。
    

---

# 二、KD-Tree 的基本原理

KD-Tree 全称：

> K-Dimensional Tree，K 维树。

这里的 K 表示向量维度。

它的核心思想是：

> 每次选择一个维度，用一条与坐标轴垂直的平面把数据分成两半。

在二维空间里，是用水平线或竖直线切分；在三维空间里，是用平面切分；在高维空间里，则是用超平面切分。

---

# 三、KD-Tree 怎样构建

假设有二维点：

```text
A = (2, 3)
B = (5, 4)
C = (9, 6)
D = (4, 7)
E = (8, 1)
F = (7, 2)
```

## 第一步：选择切分维度

根节点可以选择 x 轴。

按照 x 坐标排序：

```text
A(2,3), D(4,7), B(5,4), F(7,2), E(8,1), C(9,6)
```

选中间点 F：

```text
F = (7,2)
```

作为根节点。

于是：

```text
x < 7 的点放左边
x ≥ 7 的点放右边
```

得到：

```text
左侧：A、D、B
根：F
右侧：E、C
```

几何上相当于用：
$$x=7$$
这条竖线切分空间。

---

## 第二步：下一层换一个维度

左子树改用 y 轴切分。

左边三个点按 y 排序：

```text
A(2,3), B(5,4), D(4,7)
```

中间点 B 成为节点：

```text
B = (5,4)
```

于是：

```text
y < 4：A
y ≥ 4：D
```

右子树也按照 y 轴继续切分。

最终树大致是：

```text
              F，按 x 切分
             /            \
       B，按 y 切分       C，按 y 切分
        /       \          /
       A         D        E
```

通常切分维度可以：

1. 按 `x → y → z → x` 循环；
    
2. 选择当前方差最大的维度；
    
3. 选择数据分布最分散的维度。
    

选择中位数作为节点，是为了尽量让树保持平衡。

---

# 四、KD-Tree 查询时具体怎么找

假设查询点是：
$$q=(6,3)$$

目标是找到离它最近的点。

## 第一步：沿树向下走

根节点 F：

```text
F = (7,2)
当前切分维度：x
```

因为查询点：
$$q_x=6<7$$
所以先走左子树。

来到 B：

```text
B = (5,4)
当前切分维度：y
```

因为：
$$q_y=3<4$$
继续进入 B 的左子树，来到 A。

这条路径是：

```text
F → B → A
```

这一步只根据查询点落在切分平面的哪一侧决定方向，类似普通二叉搜索树。

---

## 第二步：记录当前最近点

计算查询点到 A 的距离：

$$d(q,A)
=
\sqrt{(6-2)^2+(3-3)^2}
=4$$
于是当前最佳结果为：

```text
best = A
best_distance = 4
```

可以把它理解成，以查询点 q 为圆心、半径 4 画一个搜索圆。

所有真正可能更近的点，都必须落在这个圆里。

---

## 第三步：回溯并检查父节点

回到 B，计算：
$$d(q,B)
=
\sqrt{(6-5)^2+(3-4)^2}
=
\sqrt 2
\approx1.41$$
B 比 A 更近，所以更新：

```text
best = B
best_distance = 1.41
```

搜索圆的半径从 4 缩小为 1.41。

KD-Tree 在最坏情况下，确实可能从叶子节点一路回溯到根节点。回溯本身没有“到某一层就强制停止”的固定层数限制。它真正的停止条件是：

> 所有可能包含更近结果的分支都已经搜索完，剩余分支都能被剪枝。
### 为什么剪掉一侧后还要继续向上

假设你在节点 B 判断：

```
B 的另一侧 E 可以剪掉
```

这并不代表 A 的另一侧 C 也可以剪掉。

因为 A 和 B：

- 切分维度可能不同；
- 切分位置不同；
- 查询点到各自切分平面的距离不同。

例如：

```
B 层：
查询点离 B 的切分面很远
→ E 可以剪枝

A 层：
查询点离 A 的切分面很近
→ C 仍然必须搜索
```

所以即使某一层另一侧被剪掉，仍然要继续回溯到父节点。

---

# 五、KD-Tree 最关键的剪枝逻辑

现在需要判断：B 的另一侧子树 D 是否值得搜索。

B 使用 y 轴切分，切分线为：

[  
y=4  
]

查询点到这条切分线的最短距离是：
$$|q_y-4|=|3-4|=1$$
当前最佳距离是：

[  
1.41  
]

因为：

[  
1<1.41  
]

说明搜索圆穿过了切分线。

因此，切分线另一侧仍然可能存在更近的点，需要检查 D。

反过来，假如当前最近距离只有 0.5：
$$|q_y-4|=1>0.5$$
那么查询点半径 0.5 的搜索圆根本碰不到切分线另一侧。

这时就可以确定：

> 另一侧的所有点都不可能比当前结果更近。

于是直接剪掉整棵子树。

---

## KD-Tree 的剪枝判断

对于当前切分维度 (j)，切分值为 (s)，查询点为 (q)，当前最佳距离为 (r)。

查询点到切分超平面的距离为：
$$|q_j-s|$$
如果：
$$|q_j-s|>r$$
那么另一侧可以剪枝。

如果：
$$|q_j-s|\leq r$$
则另一侧仍可能存在更近点，需要继续搜索。

---

# 六、KD-Tree 的查询流程总结

```text
从根节点开始
    ↓
按照当前切分维度判断走左边还是右边
    ↓
一直走到叶子
    ↓
计算并记录当前最近距离
    ↓
向上回溯
    ↓
检查查询球是否跨过切分平面
    ├── 不跨过：剪掉另一侧子树
    └── 跨过：搜索另一侧子树
    ↓
返回最近点
```

对于 Top-K 查询，不再只保存一个最近点，而是维护一个大小为 K 的最大堆。

堆中最远结果的距离，充当当前搜索半径。

---

# 七、VP-Tree 的基本原理

VP-Tree 全称：

> Vantage-Point Tree，视点树或基准点树。

它不按照 x、y、z 坐标轴划分，而是：

> 选择一个点作为“视点”，根据其他点离这个视点的距离，把数据分成内外两组。

因此，VP-Tree 依赖的是距离，而不是坐标方向。

---

# 八、VP-Tree 怎样构建

假设有若干点，先选择一个点 (v) 作为 Vantage Point：

```text
v = 视点
```

然后计算其他所有点到 (v) 的距离：
$$d(v,x_1),d(v,x_2),\ldots,d(v,x_n)$$
假设距离排序为：

```text
1.2, 1.8, 2.1, 3.0, 4.2, 5.3, 6.1
```

取中位数，例如：
$$\mu=3.0$$
将点分成两组：

```text
内侧子树：
d(v,x) < 3.0

外侧子树：
d(v,x) ≥ 3.0
```

几何上类似于以 (v) 为圆心、半径 3 画圆：

```text
圆内的点 → 左子树
圆外的点 → 右子树
```

在高维空间中，这不是圆，而是超球面。

然后对内侧和外侧的数据递归重复上述过程：

```text
                  视点 v
                 半径 μ
              /          \
      距离小于 μ          距离大于等于 μ
       内侧子树              外侧子树
```

---

# 九、VP-Tree 查询时具体怎么找

假设某个节点：

- 视点为 (v)；
    
- 划分半径为 (\mu=5)；
    
- 查询点为 (q)。
    

先计算：

[  
d=d(q,v)  
]

假设：

[  
d(q,v)=3  
]

因为：

[  
3<5  
]

说明查询点位于视点划分球的内部，所以先搜索内侧子树。

---

## 记录当前最近距离

假设目前找到的最近结果与查询点的距离为：
$$\tau=1$$
那么所有可能更好的点必须位于：

> 以查询点 q 为中心、半径 1 的搜索球内。

现在问题是：这个搜索球有没有可能碰到外侧区域？

查询点到视点的距离是 3，搜索半径是 1。

因此搜索球中的点到视点的最大可能距离为：
$$d+\tau=3+1=4$$

而外侧区域要求：
$$d(v,x)\geq5$$
因为：

[  
4<5  
]

所以搜索球完全处于内侧，根本碰不到外侧区域。

因此整个外侧子树都可以剪掉。

---

# 十一、VP-Tree 的剪枝条件

设：

- (d=d(q,v))：查询点到视点的距离；
    
- $\tau$：当前最佳搜索半径；
    
- $\mu$：内外分区阈值。
    

## 是否需要搜索内侧子树

内侧点满足：

$$d(v,x)<\mu$$
如果：

$$d-\tau>\mu$$

说明查询球整体位于外侧，内侧子树不可能有答案，可以剪枝。

因此，需要搜索内侧的条件是：

$$d-\tau\leq\mu$$

---

## 是否需要搜索外侧子树

外侧点满足：
$$d(v,x)\geq\mu$$
如果：
$$d+\tau<\mu$$

说明查询球整体位于内侧，外侧子树可以剪枝。

因此，需要搜索外侧的条件是：
$$d+\tau\geq\mu$$

---

# 十二、VP-Tree 的完整搜索过程

假设：
$$d(q,v)<\mu$$
查询流程是：

```text
先搜索内侧子树
      ↓
更新当前最近距离 τ
      ↓
判断 d + τ 是否达到 μ
      ├── 否：搜索球碰不到外侧，剪枝
      └── 是：搜索球跨过边界，还要搜索外侧
```

反过来，如果：

$$d(q,v)\geq\mu$$
则先搜索外侧子树，再判断是否有必要返回内侧。

---

# 十三、KD-Tree 和 VP-Tree 的核心区别

|特征|KD-Tree|VP-Tree|
|---|---|---|
|分区依据|某一坐标维度|到视点的距离|
|分区形状|轴对齐超平面|超球面|
|是否依赖坐标|是|不强依赖具体坐标|
|剪枝依据|查询球是否跨过切分平面|查询距离区间是否跨过划分半径|
|常用距离|欧氏距离|任意满足三角不等式的度量|
|适合数据|低维欧氏空间|一般度量空间|
|典型问题|几何点最近邻|无自然坐标轴、但有距离函数的数据|

---

# 十四、VP-Tree 为什么适用范围更广

KD-Tree 必须访问向量的具体坐标：

```text
第 1 维是多少
第 2 维是多少
第 3 维是多少
```

因为它需要按照坐标轴切分。

VP-Tree 只需要一个距离函数：

```text
distance(a, b)
```

只要这个距离满足度量空间的基本性质，尤其是三角不等式，就可以使用 VP-Tree。

例如理论上可以用于：

- 欧氏距离；
    
- 曼哈顿距离；
    
- 汉明距离；
    
- 某些编辑距离；
    
- 其他满足度量性质的距离。
    

需要注意，通常使用的：

[  
1-\text{cosine similarity}  
]

不一定在所有情况下都严格满足三角不等式；归一化向量上的角距离或欧氏距离更适合严格的度量树推导。

---

# 十五、为什么它们在高维空间会失效

文档说它们在低维有效，但面对高维 Embedding 会遇到维度灾难。

这里的“失效”通常不是结果错误，而是：

> 剪枝越来越困难，最终不得不搜索树的大部分节点。

---

## KD-Tree 在高维的问题

假设是 1024 维向量。

每个节点只按照一个维度切分，但查询点周围的搜索球可能在很多维度上跨越边界。

查询时经常出现：

```text
左子树可能有结果
右子树也可能有结果
```

于是两边都要搜索。

当维度很高时，大量分割平面都会与搜索区域相交，剪枝效果大幅下降。

最终可能变成：

```text
走左边
回溯后还要走右边
几乎所有子树都不能剪掉
```

复杂度逐渐接近：

[  
O(n)  
]

---

## VP-Tree 在高维的问题

高维空间中常出现“距离集中”：

> 随着维度升高，最近点和最远点的距离差距相对变小。

例如低维中，距离可能分布为：

```text
1、2、3、10、20
```

内外区域很好区分。

高维中可能集中为：

```text
31.2、31.5、31.7、32.0、32.3
```

查询球很容易同时跨过 VP-Tree 的内外边界。

结果就是：

```text
内侧子树需要搜索
外侧子树也需要搜索
```

剪枝效率也会下降。

---

# 十六、为什么 RAG 通常不用它们

文本 Embedding 通常是：

```text
384 维
768 维
1024 维
1536 维
3072 维
```

这已经远超 KD-Tree 通常表现较好的低维范围。

因此生产级 RAG 更常用：

- HNSW；
    
- IVFFLAT；
    
- IVF-PQ；
    
- 其他 ANN 方法。
    

KD-Tree、VP-Tree 更适合：

- 低维空间；
    
- 数据规模不是特别大；
    
- 需要精确最近邻；
    
- 距离计算满足对应结构的要求。
    

---

# 十七、用一句话区分

**KD-Tree：**

> 轮流按照不同坐标轴把空间切成左右两半，查询时根据搜索球是否跨过切分平面决定是否回头搜索另一边。

**VP-Tree：**

> 选择一个视点，按照到该点的距离把数据分为球内和球外，查询时利用三角不等式判断另一侧是否可能包含更近结果。

它们都依靠“剪枝”提速：

```text
KD-Tree：
证明另一侧空间离 Query 太远

VP-Tree：
证明另一侧距离区间与 Query 的搜索半径不相交
```

而高维空间中，这种“证明不可能”的机会越来越少，所以它们最终容易退化成接近全量扫描。
